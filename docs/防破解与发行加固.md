# 《晚自习之后》防破解与发行加固指南

面向 Godot 4 + Android 的单机文字 AVG。本文分两部分：

1. **本工程已经做了什么**（代码里已落地）
2. **发行前你需要自己做什么**（需要密钥、签名、渠道配合）

---

## 先说结论：单机游戏无法做到「不可破解」

任何在玩家设备上运行的程序，最终都能被逆向。业界共识是：

> 目标不是「杜绝破解」，而是**把破解成本抬高到超过收益**，
> 同时**不伤害正常玩家的体验**。

尤其对文字 AVG 来说，过度加密会带来加载卡顿、存档丢失、
杀毒误报等真实损失，而这些损失全部由**正版玩家**承担。
所以下面的方案按「性价比」排序，并明确标注哪些**不建议做**。

---

## 一、已在本工程落地的保护

### 1. 存档签名校验（`save_system.gd`）

存档是明文 JSON，玩家可以直接编辑。原先改一个数字就能解锁真结局。

现在写入时附加 SHA-256 签名：

```gdscript
const SAVE_SALT := "AfterEveningStudy::2015-05-17::42"

func _sign(payload: Dictionary) -> String:
    var d := payload.duplicate(true)
    d.erase("_sig")
    var keys := d.keys()
    keys.sort()                      # 键排序，保证签名稳定
    var ordered := {}
    for k in keys:
        ordered[k] = d[k]
    return (JSON.stringify(ordered) + SAVE_SALT).sha256_text()
```

**设计取向：检测而非拒绝。**
签名不符时**照常读档**（不让玩家丢进度），但打上 `_tampered` 标记，
结局判定回落到空席结局：

```gdscript
func determine_ending() -> String:
    if save_tampered:
        return "ending_empty_seat"
```

理由：改档解锁真结局的玩家，会跳过整段体验，
然后可能得出「这游戏结局莫名其妙」的结论。挡住这一条即可，
不必因为玩家想调高理智值就惩罚他。

> ⚠️ `SAVE_SALT` 是硬编码的，逆向可读。这只挡随手改 JSON 的人，
> 挡不住真正的逆向者——**这就是本方案的设计上限，是有意为之**。

### 2. 资源不以散文件形式暴露

导出 `.apk` / `.pck` 时，所有 `.avg` 剧本、PNG、WAV 都被打包进 `.pck`，
不是文件夹里可直接双击打开的散件。默认已经挡住了「解压就看到全部剧情」。

### 3. 逻辑三端一致校验

`game_state.gd` / `simulate.py` / `player.js` 三处结局判定完全同步，
并由 `tools/check_js_runtime.js` 每次构建前比对。
这不是防破解措施，但能防止**因为改了一处忘了另一处**而产生
「某条路线永远拿不到真结局」这类会被误认为破解补丁导致的 bug。

## 二、发行前需要你自己做的

### 1. 开启 PCK 加密（最重要，性价比最高）

Godot 4 原生支持用 AES-256 加密 `.pck`。这一步能挡住绝大多数
「用 GDRE / godotpcktool 一键解包提取剧本和美术」的行为。

**步骤：**

```bash
# 1. 生成 32 字节（64 位十六进制）密钥
openssl rand -hex 32 > pck_key.txt

# 2. 设置环境变量
export GODOT_SCRIPT_ENCRYPTION_KEY=$(cat pck_key.txt)

# 3. 必须用「带加密支持的导出模板」重新编译，官方预编译模板不含此功能
#    详见 Godot 文档 Compiling with PCK encryption key
```

在导出预设里勾选 **Encrypt Exported PCK**，并填入同一密钥。

> **务必**把 `pck_key.txt` 加入 `.gitignore`，绝不要提交进仓库。
> 密钥一旦泄漏，加密等于没做。

### 2. Android 签名与最小权限

```bash
keytool -genkey -v -keystore release.keystore \
  -alias aes -keyalg RSA -keysize 4096 -validity 10950
```

- keystore 与口令**离线保存**，不入库
- 导出预设里关掉所有用不到的权限。本作是纯单机文字游戏，
  **不需要网络、定位、读写外部存储、录音、摄像头**——
  权限越少，越不容易被套壳重打包后植入广告 SDK

### 3. 关掉调试出口

导出 Release 版时确认：

- 不勾选 `Export With Debug`
- 关闭远程调试端口
- `project.godot` 里移除任何调试快捷键 / 秘籍指令

本工程的 `tools/preview/` 是**开发用的浏览器预览器**，
里面有完整剧本 JSON。**发行包不要包含 `tools/` 目录**
（当前打包脚本会带上，正式发行时请手动排除）。

### 4. 完整性自检（可选）

在启动时校验关键资源的哈希，被替换则提示：

```gdscript
func _verify_assets() -> bool:
    var f := FileAccess.open("res://story/50_final.avg", FileAccess.READ)
    if f == null:
        return false
    return f.get_as_text().sha256_text() == EXPECTED_FINAL_HASH
```

作用有限（哈希常量同样可被改），但能挡住「替换剧本文件搞恶搞版本」。

### 5. 渠道层面

- **Google Play**：启用 Play Integrity API，可判断安装来源是否正版
- **Steam**：接入 Steamworks 的 `SteamAPI_RestartAppIfNecessary`，
  挡住直接拷贝 exe 运行
- **国内渠道**：多数渠道 SDK 自带包名与签名校验

## 三、明确不建议做的

| 做法 | 为什么不建议 |
|---|---|
| 联网验证正版 | 单机文字游戏强制联网，会在断网、服务器关停后**让正版玩家玩不了**，是口碑自杀 |
| 加壳 / 反调试 / VMProtect | Android 上极易被杀毒软件误报为病毒，且拖慢启动 |
| 检测到破解就删档 / 静默降智 | 一旦误判就是灾难；且这类"惩罚彩蛋"一旦被公开，反而成为破解者的炫耀点 |
| 自研加密算法 | 几乎必然弱于标准 AES，且容易出 bug 导致存档损坏 |
| 剧本文本混淆 | 文字游戏的剧本终究要显示给玩家看，内存里必然是明文，混淆只增加自己的维护成本 |

## 四、对文字 AVG 更有效的思路

破解一份文字游戏的**技术成本很低**，但盗版对本作的伤害其实主要来自
「剧透传播」而非「少卖一份」。因此更值得投入的是：

1. **多结局与隐藏线索的体验不可替代**
   本作五个结局、517 个节点、真结局需要跨四章收集证据链——
   看别人的通关视频≠自己玩。这本身就是最好的防护。

2. **持续更新绑定正版渠道**
   后续追加的支线、差分立绘只在正版渠道推送，盗版停留在旧版本。

3. **成就 / 图鉴云同步**（若上架 Steam）
   线索图鉴、结局收集与平台成就绑定，盗版拿不到。

4. **发行前不要提前泄漏剧本**
   本仓库的 `docs/剧本全文.md` 是开发用文档，
   **公开发行前请从仓库移除或转为私有**。
